## The five path traces

Every file and line below was read on this checkout, not quoted from a stage record.

### 1. Quit, from before-quit to the last joined owner

`app.on('before-quit')` at src/main/index.ts:645 runs `markAppQuitting()` at line 654, synchronously, before `event.preventDefault()` and before any await. The state lives in src/main/lifecycle.ts (the setter at line 60, one way by design, and src/main/__tests__/quit-admission.test.ts pins the export surface so no way back can appear). From that instant the one invoke registrar refuses every new renderer request: src/main/typed-ipc.ts:50 checks `appLifecycleState() === 'quitting'` and throws the typed SHUTTING_DOWN refusal, and because ipc-single-bridge.test.ts holds that wrapper as the only registrar, one check closes all 190 channels. The ordered teardown is `disposeMainCapabilities` in src/main/capabilities.ts: the clone cancel at line 346, `await shutdownGmuxCore()` at line 351 (snapshots and the manifest quit generation inside it), the synchronous feed stops, then the remote execution ledger at lines 395 to 397, being `beginRemoteExecutionShutdown()`, `cancelRemoteExecutions()` and `await joinRemoteExecutions()` (src/main/machines/execution-ledger.ts:274, 542 and 586), then the bounded watcher drain, the worker disposals, `reapGuardedChildren()` at line 457, and the late drain at line 526 whose only two exits are a clean quit or a truthful SIGKILL after `clearLogRunSentinel()`. The last joined owner on the ordinary path is the watcher drain; the last joined owner that touches another machine is the execution ledger at line 397.

### 2. A journaled clone, from durable declaration to the restart notice

The clone verb at src/main/machines/remote-clone.ts:280 sends its work through `runRemoteWrite` with `execution: { kind: 'clone', subject: input.path, machineLabel: label }` at line 286. The exec plane hands every such start to `admitRemoteExecution` (src/main/machines/exec-plane.ts:616 and 736), and the ledger writes the durable row BEFORE any child is spawned: src/main/machines/execution-ledger.ts:379 calls `journal.beginRemoteExecution`, which is the manifest store at src/main/manifest/store.ts:554 over src/main/manifest/remote-executions.ts:173, synchronous better-sqlite3, so there is no window between the row committing and the spawn. When the row cannot be written the ledger refuses with FS_FAILED carrying REMOTE_EXEC_NOT_RECORDED (lines 368 to 397), the clone catch asks `isRemoteExecUnjournaled` FIRST at remote-clone.ts:307 and answers with the refused sentence that names no path, because nothing crossed. That order is stage 2 of the plan, and src/main/machines/__tests__/remote-clone.test.ts and execution-ledger.test.ts pin it. The restart half: `setRemoteManifest` at src/main/machines/remote-record.ts:177 calls `resolveCutOffRemoteExecutions` (execution-ledger.ts:635), which closes every unfinished row as cutOff and posts one durability notice at line 650. `postDurabilityNotice` (src/main/notice/index.ts:77) broadcasts `scrollback:notice` (src/shared/ipc/terminal.ts:412) or queues it until the renderer drains `notice:pending` (src/shared/ipc/sessions.ts:238), so a person who quit mid copy is told at the next launch, once.

## The named exceptions

**Exception 1, and it is the point withheld.** `smoke:matrix` fails rows 1 and 5, transport loss and clock skew, with the same sentence on this tree and on the clean parent at `f929080`: a row that should have held its status moved between idle and running. The graders are in build/remote-matrix.mjs at lines 712 to 738: on row 1 the session on the machine that was never cut, and the session on this Mac, must each hold one status for the whole watch window. The harness's last recorded green run is from the Phase 72 era on 2026-08-18, and the status ladder, the hold window and the resume witness all moved deliberately after that date. So either a later phase drifted the status truth under those two faults, which is a real failure flow defect, or the harness asserts a stillness the product deliberately no longer promises, which is a test seam defect. Nobody has adjudicated it, this audit could not inside its budget (the main leg watches timed windows for roughly forty minutes), and an adversarial audit does not award a point over a red Tier 3 harness on the strength of the friendlier reading. The point comes back when the adjudication phase either turns the matrix green or corrects its expectations with evidence and a recorded ruling. Row 9 also flapped once on a quiet run, one capture pass still in flight after the row finished, and belongs to the same phase.

**Exception 2, recorded and not scored.** The hermetic checks gate exempts one file from its npx rule by name: build/assert-electron-teardown.mjs matches the string npx only inside a regex that catches `npx electron`, and spawns nothing through it. The exemption is a single name with the reason beside it, the narrow shape the guardrails allow, and it is recorded here so a later round widening that list has to argue with this sentence.

**Also recorded:** stage 4's battery found the matrix red and correctly refused to patch it inside a structural stage; stage 5's near miss, a lane variable first named GMUX_TEST_LANE that the contract inventory rightly counted as a durable name, was renamed to VITEST_LANE before landing and the inventory stayed byte for byte. Both records match the tree.
